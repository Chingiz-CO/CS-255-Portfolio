# CS 255 System Analysis and Design Portfolio

## DriverPass Project Summary

The client for this project was DriverPass, a company that wanted to improve driver training and help students prepare for DMV driving tests. DriverPass wanted a web-based system that would allow customers to access online classes and practice tests, schedule driving lessons, manage appointments, and track their training progress. The system also needed to support employees such as the owner, IT officer, secretary, and drivers by providing different levels of access and tools for managing customers, reservations, reports, and accounts.

## What I Did Well

One area I did particularly well was translating the client's requirements into a structured system design. I identified the different users of the DriverPass system and connected their needs to specific system functions. I also created UML diagrams that showed how users would interact with the system, how activities would flow, how objects would relate to each other, and how important processes such as scheduling appointments would work.

## What I Would Revise

If I could revise one part of my work, I would improve some of the UML diagrams by making the relationships and flows even more detailed. For example, I could add additional exception paths for scheduling conflicts, unavailable vehicles, or account problems. I would also review the diagrams again to make sure the visual layout is as clear as possible and that someone unfamiliar with the project could understand them quickly.

## Interpreting User Needs

I interpreted the user's needs by reviewing the DriverPass interview and identifying the functions that each type of user required. Customers needed to schedule and manage driving lessons, access online learning materials, take practice tests, and reset their passwords. The secretary needed to register customers and manage appointments, while the IT officer needed to maintain accounts and control access. I used these requirements when designing the system and its UML diagrams.

Considering user needs is important because the purpose of a software system is to solve problems for the people who use it. A technically correct system can still fail if it does not match the users' expectations or make their tasks easier. Understanding those needs early helps prevent unnecessary features, missing functionality, and expensive changes later in development.

## My Approach to Software Design

My approach to designing software is to first understand the problem and gather clear requirements before deciding how the system should be structured. I then identify the users, important system functions, data that must be stored, and relationships between different parts of the system. UML diagrams are useful because they allow me to visualize the system before implementation begins.

In future projects, I would continue using requirement analysis, use cases, activity diagrams, sequence diagrams, and class diagrams to organize the design. I would also continue reviewing the design against the original requirements throughout the process so that the final system remains focused on the client's needs.
